S1 is done: the new `valgen_core.py` replaces the project copy and runs end to end, but only on a synthetic JST series. I didn't have the real JST file, so none of the numbers below are real results. I did not do S5 (tables and charts), as you asked.

**What changed in `valgen_core.py`**
- **Kernel wrapper:** `run_family3` is now a ledger wrapper over `wdt_kernel`. With the reset and waiver off it matches the old engine to 1.5e-15 over 504 runs, and the batched search matches single runs to about 1e-15.
- **Retired:** `reset_interval` and `death_waiver` now raise a TypeError, and nothing reads them. Death always auctions Route D.
- **Independent hazards:** λ_C and λ_D are separate, and `data['p3_lambda_grid']` holds the λ_C × λ_D grid under the candidate rule.
- **Voluntary reset:** reset is now a strategy action (cycles 5, 10, 20 years). `p3_reset_sensitivity` now holds the voluntary-reset cycles.
- **Route B:** the lien and income modes are in the strategy library (b_election, route_shift).
- **HSC:** it is now honest error plus shock, reported as the extra cost over the base rule set.
- **V0 sweep:** `data['v0_sweep']` runs across the RATES revenue bands, at the baseline route mix.
- **Bridge:** it now runs on a JST real-return series. `N_fill` and `scenario_start_year` are gone from `meta` and `_validate`.
- **Contract keys:** `data['replay']`, `data['p6']` and `data['rho']` are all still produced.
- **HLC pair:** it reads the RATES burdens through `load_json`, so valgen never imports `rates_core`. It is skipped, with the reason recorded, because `rates_data.json` is absent here.

**Numbers that will change on the real run** (the figures below are synthetic)
- The scheduled reset is gone, so the strategy library, the reset sensitivity table and the "resets reduce D understatement" check all change.
- The best voluntary reset (every 5 years, α_D = 1) gains +1.6% under the candidate rule at λ = 5%, so BRG fails on that run.
- Worst-case (λ = 0) best response is +53% under the candidate rule; the base rule is higher still.
- λ_D defaults to λ_C when `verification.lambda_D` is 0, so the existing grids stay comparable.
- `rows['W']` is now declared wealth after the year's settlement.
- Single `run_family3` calls are about 12× slower, so a full run took 6.5 minutes.
