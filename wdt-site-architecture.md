# WDT Site Architecture

**Project:** Public-facing GitHub Pages website for the Wealth Delta Tax research programme
**Generator:** Quarto (non-negotiable)
**Root directory:** `wdt-site/`

The site takes Markdown source files for 26 WDT papers, preprocesses them into Quarto-ready `.qmd` files, and publishes the result as a static HTML site via GitHub Pages. The build has two sequential Python steps followed by a Quarto render.

---

## Build sequence

```
wdt-contents.yml ──► build_anchors.py ──► anchors.yml
                                               │
source_md/*.md ─────────────────────────────► preprocess.py ──► _build/ ──► quarto render
paper_registry.yml ──────────────────────────►     │
wdt_references.json ─────────────────────────►     │
static/ ─────────────────────────────────────►     │
```

Run order: `build.bat` → `build_anchors.py` → `preprocess.py` → `quarto render _build`

---

## Top-level files

### `build.bat`
**What it does:** Windows batch script that runs the full build in sequence.
**Inputs:** none (invokes the two Python scripts)
**Outputs:** none directly — side-effects are the outputs of the scripts it calls
**Dependencies:** Python, `build_anchors.py`, `preprocess.py`
**Dependants:** none (entry point)

---

### `wdt-contents.yml`
**What it does:** Master content map. Declares every paper (shortcode, output HTML filename, title) and every numbered section within each paper, in order. This is the authoritative source of truth for what sections exist and what they are called.
**Inputs:** maintained by hand
**Outputs:** consumed by `build_anchors.py` and `preprocess.py`
**Dependencies:** none
**Dependants:** `build_anchors.py`, `preprocess.py`

Papers covered: WP, MF, LR, LR.A, LR.B, JUR, VAL, VAL.A, VAL.B, CORP, CORP.A, GOV, GOV.A, GOV.B, RATES, RATES.A, BEHAV, CLOSE, POL, PHASE1, ENV, SWEEPS, SWEEPS.A, FM, MOD, SCOPE (26 papers total).

---

### `build_anchors.py`
**What it does:** Derives the Quarto-generated HTML anchor ID for every section declared in `wdt-contents.yml`, then writes `anchors.yml`. Encodes Quarto's anchor rules: numeric top-level headings slugify the title; numeric sub-sections strip the number prefix; letter-prefixed sections (appendix and VAL.B style) keep the full prefix. This logic is subtle and must be kept in sync with Quarto's actual rendering behaviour.
**Inputs:** `wdt-contents.yml`
**Outputs:** `anchors.yml`
**Dependencies:** `wdt-contents.yml`, PyYAML
**Dependants:** `preprocess.py` (reads `anchors.yml` to resolve deep links)

Key rules encoded:
- Pure integer top-level (`"1"`) → slugify title only
- Numeric sub-section (`"1.1"`) → strip number, slugify title only
- Single letter A–H → appendix style, dot added: `"A. Title"` → `a.-title`
- Single letter I–Z → VAL.B style, no dot: `"J Title"` → `j-title`
- Letter-dot-numeric (`"A.1"`) → full prefix kept: `"A.1 Title"` → `a.1-title`

---

### `anchors.yml`
**What it does:** Flat key→value map from every `PAPER§SECTION` lookup key to its resolved `page.html#anchor-id` URL. Used by `preprocess.py` to convert in-text cross-references into working hyperlinks.
**Inputs:** generated by `build_anchors.py`
**Outputs:** consumed by `preprocess.py`; also copied as a static endpoint into `_build/` for machine-readable access at `/anchors.yml`
**Dependencies:** `build_anchors.py` must run first
**Dependants:** `preprocess.py`

Example entries:
```yaml
WP§3.5: wp.html#the-symmetric-loss-refund-mechanism
GOV.B§A.1: gov-b.html#a.1-the-taxpayer-chamber-tp
VAL.B§J: val-b.html#j-the-deferred-delta
```

---

### `paper_registry.yml`
**What it does:** Maps each paper shortcode to its source file glob pattern and its output `.qmd` filename in `_build/`. Decouples the source filename convention (which includes version numbers and dates) from the stable output names that anchors and cross-links depend on.
**Inputs:** maintained by hand; source files live in `source_md/`
**Outputs:** consumed by `preprocess.py`
**Dependencies:** none
**Dependants:** `preprocess.py`

Each entry has three fields:
- `shortcode` — e.g. `WP`
- `source_glob` — e.g. `"1.0_*_Wealth_Delta_Tax_Whitepaper.md"` (glob allows version number variation)
- `output` — e.g. `wp.qmd`

---

### `wdt_references.json`
**What it does:** Master reference database for the project. Contains 128 external references with full bibliographic data, 26 internal paper records (shortcode, version, status, relationships), 378 citation records linking references to specific paper sections, and 28 open flags tracking bibliographic errors and orphan references.
**Inputs:** maintained and extended by the `wdt-reference` skill
**Outputs:** consumed by `preprocess.py` for front matter injection (title, version, date, keywords), JSON-LD structured data generation, the `/corpus` paper index page, and the `/references` bibliography page. Also copied as a static endpoint into `_build/` at `/wdt_references.json`.
**Dependencies:** none (source of truth)
**Dependants:** `preprocess.py`

Top-level structure:
```
meta                     — database version, session log, counts
external_references[]    — 128 entries with full bibliographic data
internal_papers[]        — 26 WDT paper records
citations[]              — junction table: ref × paper × section
flags[]                  — 28 open bibliographic issues
```

---

### `preprocess.py`
**What it does:** The main build pipeline. Reads source `.md` files, transforms them, and writes `.qmd` files to `_build/`. Also generates two auto-built pages (`corpus.qmd`, `references.qmd`), copies static assets, copies machine-readable data files as static endpoints, generates `site-index.json`, and rewrites `_quarto.yml` to inject a two-level nested sidebar and disable the right-hand TOC.

**Inputs:**
- `source_md/*.md` — paper source files (read via `paper_registry.yml` globs)
- `paper_registry.yml` — source→output mapping
- `wdt-contents.yml` — section hierarchy (for sidebar and site-index generation)
- `anchors.yml` — section→URL map (for cross-reference conversion)
- `wdt_references.json` — paper metadata (for front matter and structured data)
- `static/` — all static assets and hand-authored pages

**Outputs (all in `_build/`):**
- `*.qmd` — one per paper, preprocessed from source
- `corpus.qmd` — auto-generated paper index page
- `references.qmd` — auto-generated external bibliography page
- `site-index.json` — merged single-fetch navigation index
- `wdt_references.json` — copy of source database as static endpoint
- `anchors.yml` — copy as static endpoint
- `wdt-contents.yml` — copy as static endpoint
- `_quarto.yml` — rewritten with nested sidebar and `toc: false`
- All files from `static/` — copied flat or preserving structure

**Processing steps applied to each paper:**
1. Strip LaTeX artifacts (`\newpage`, `\medskip`, `\tableofcontents`, etc.)
2. Convert cross-references to hyperlinks — patterns `(PAPER §X.Y)` and `PAPER §X.Y` → `[original text](resolved-url)`
3. Convert internal bibliography lines to styled `:::` divs
4. Inject YAML front matter metadata (description, author, date, version, keywords) from `wdt_references.json`
5. Inject JSON-LD `ScholarlyArticle` structured data block

**Dependencies:** `anchors.yml`, `paper_registry.yml`, `wdt-contents.yml`, `wdt_references.json`, `static/`, PyYAML
**Dependants:** Quarto (consumes `_build/`)

**Key constants:**
- `SITE_URL = "https://wealthdeltatax.org"`
- `AUTHOR = "K. Ogata"`
- Source: `source_md/`, Build: `_build/`, Static: `static/`

## Sub-directories

### `.github/`
Contains a single sub-directory `workflows/` with one file: `deploy.yml`.

**`deploy.yml`** — GitHub Actions workflow that builds and deploys the site automatically on every push to `main` (and on manual trigger).

Build steps in order:
1. Checkout repo
2. Set up Python 3.11
3. Install Quarto (via `quarto-dev/quarto-actions/setup@v2`)
4. Install Python dependencies (`pip install pyyaml`)
5. Run `python preprocess.py` — generates `_build/`
6. Run `quarto render _build` — renders `.qmd` → HTML into `_build/_site/`
7. Upload `_build/_site/` as the Pages artifact
8. Deploy to GitHub Pages

Note: the workflow runs `preprocess.py` directly (not `build.bat`), and does **not** run `build_anchors.py` separately — `anchors.yml` must therefore be committed to the repo and kept up to date whenever `wdt-contents.yml` changes. The debug steps (`find _build`, `find _build/_site`) remain in place and run on failure.

**Dependencies:** committed `anchors.yml`, committed `paper_registry.yml`, committed `wdt-contents.yml`, committed `wdt_references.json`, all `source_md/` files, all `static/` files.
**Dependants:** GitHub Pages deployment.

---

### `source_md/`
Hand-authored Markdown source files for all 26 papers. **Read-only from the pipeline's perspective — never modified by any script.**

Filename convention: `N.N_YYMMDD_WDT_[Title].md` where `N.N` is the paper sequence number and `YYMMDD` is the version date (e.g. `1.0_260810_Wealth_Delta_Tax_Whitepaper.md`). The version-date component is what the glob patterns in `paper_registry.yml` are designed to tolerate — the `*` wildcard absorbs the date, keeping output filenames stable across revisions.

All 26 papers live here. They contain LaTeX artifacts, cross-reference shorthand, and APA prose citations that `preprocess.py` transforms before Quarto sees them.

---

### `static/`
Static assets and hand-authored content copied into `_build/` at build time. Contains three sub-directories.

#### `static/pages/`
Hand-authored `.qmd` pages. These are **flattened** into the `_build/` root by `preprocess.py` (the `pages/` path component is stripped). Current pages:

| File | Served at | Purpose |
|------|-----------|---------|
| `index.qmd` | `/index.html` | Site home page. Introduces the WDT, comparison table vs conventional wealth tax, entry points by reader type, full paper listing by category. Includes site-level and `ScholarlyArticle` JSON-LD. References Zenodo DOI `10.5281/zenodo.21964119`. |
| `start-here.qmd` | `/start-here.html` | Reader's guide. Tiered reading paths (5 min / 20 min / 1–2 hours / full programme). Key terms signpost, project status note. |
| `faq.qmd` | `/faq.html` | 12-entry FAQ with the tree-growth analogy intro. Each entry states the objection, gives the WDT answer, and cites the relevant papers. Structured as a table. Covers symmetry/revenue, crash funding, valuation, avoidance, comparison to wealth taxes, liquidity, unrealised gains, state partnership, zero-growth scenario, SWF rationale, labour tax shift, exemption threshold. |
| `glossary.qmd` | `/glossary.html` | Alphabetical definitions of ~20 recurring WDT terms, each with a deep link to the paper section where the concept is developed in full. Terms include: assessment window, cooperative architecture, CDL, delta, delta base, DR/FS/TP chambers, enumerated structural clauses, Governing Council, grandfathering baseline, LRR, membrane, must-transfer rule, non-interference constraint, position closure, public valuation register, purchase option, Routes A/B/C/D, SRR, SWF, symmetric loss-refund mechanism, voluntary settlement, wealth delta. |
| `summary.qmd` | `/summary.html` | Full overview document (the `0.0` summary paper, v3.8, 16 Aug 2026). Substantive summary of all 26 papers in sequence, plus the consolidated open questions register (5 remaining items as of v3.8). Hand-maintained; the longest page on the site. |

These pages are not generated — they are maintained by hand and copied as-is into `_build/`. They do not go through the paper preprocessing steps (no LaTeX stripping, no cross-reference conversion, no front-matter injection).

#### `static/seo/`
SEO configuration files. Flattened into the `_build/` root (i.e. served at site root). Contains three files:

**`series.yml`** — maps every paper shortcode to its output HTML filename, title, and full section hierarchy. Structurally identical to `wdt-contents.yml` — they carry the same data. `preprocess.py` loads this file as `link_map` (for `SHORTCODE → page.html` resolution in cross-reference conversion and corpus/references page generation) and also as `contents` in the sidebar and site-index generation functions. **Must be kept in sync with `wdt-contents.yml`** — if a section is added to one, it must be added to both, and `build_anchors.py` must be re-run to regenerate `anchors.yml`. The duplication is a known redundancy; a future refactor could consolidate to a single file.

**`wdt_references.bib`** — BibTeX version of the external reference database. 113 entries (converted from the `0.4` reference document on 2026-08-12; `wdt_references.json` carries 128 entries as the authoritative count). Key conventions: `AuthorYYYY` / `AuthorEtAlYYYY`, disambiguated with `a`/`b` where needed; `@article`, `@book`, `@incollection`, `@techreport` (NBER/CESifo), `@unpublished` (SSRN-only), `@misc` (institutional/gov reports); LaTeX-encoded diacritics; DOIs included where present; open flags noted inline. This file is not consumed by `preprocess.py` — it is used for the future citation-key conversion stage (Stage 1.5) where source files will move from prose APA to `@key` format for Quarto's citation rendering. Served as a static download at `/wdt_references.bib`.

**`robots.txt`** — Standard permissive crawl policy (`User-agent: * / Allow: /`) with sitemap pointer to `https://wealthdeltatax.org/sitemap.xml`. Served at `/robots.txt`. The sitemap itself is generated by Quarto at render time.

#### `static/style/`
Contains two files that are copied into `_build/` preserving the `style/` sub-path (served at `/style/`). Both are referenced by `_quarto.yml`.

**`styles.css`** — site-wide CSS. Sets Georgia serif body font (16px, 1.7 line-height), Helvetica Neue sans-serif headings, and reduced sidebar font size (0.9rem). Defines two custom classes used by `preprocess.py` output:
- `.internal-bibliography` — grey left-bordered box applied to `:::` divs generated from internal bibliography lines in source files (light grey background, 3px `#dee2e6` left border, 0.9rem font)
- `.pdf-download` — dark grey pill button (`#495057`) for PDF download links, with hover state

**`apa.csl`** — CSL stylesheet for APA 7th edition citation rendering. Referenced in `_quarto.yml` as `csl: apa.csl`. Not currently active in the pipeline (source files use prose APA, not `@key` format) but is in place for Stage 1.5 when citation-key conversion is complete.

#### `static/_quarto.yml`
The base Quarto configuration template. `preprocess.py` copies this to `_build/` first, then reads it, injects the generated nested sidebar and sets `toc: false`, and writes it back. The file in `static/` therefore represents the **pre-injection** state — the sidebar it contains is the flat fallback used only if `preprocess.py` fails or is skipped.

Key configuration:
- `project.type: website`, `output-dir: _site`
- `site-url: https://wealthdeltatax.org`
- Open Graph and Twitter Card metadata
- Search: overlay, navbar location
- **Navbar** (hand-maintained, not generated): Home, Start Here, FAQ, Full Overview, Papers, References (with dropdown of 17 main papers), Glossary
- **Sidebar** (flat fallback, overwritten by `preprocess.py`): 7 sections matching the `SIDEBAR_SECTION_ORDER` in `preprocess.py` — Core Papers, Literature, Valuation, Corporate & Governance, Revenue & Behaviour, Implementation, Analysis. The generated version adds two-level nesting (section titles as sub-items) and sets `collapse-level: 1`.
- `page-footer`: CC BY 4.0 licence left, Zenodo DOI right
- `format.html`: theme `cosmo`, `toc: true` (overridden to `false` by `preprocess.py`), `toc-depth: 3`, `css: styles.css`, `citations-hover: true`, `footnotes-hover: true`, `csl: apa.csl`
- `bibliography: wdt_references.bib`

**Note on `toc`:** The base file has `toc: true`. `preprocess.py` overwrites this to `false` because Quarto's right-hand TOC conflicts with the deep nested sidebar. If `preprocess.py` is not run (e.g. in local testing without the pipeline), papers will render with the right-hand TOC visible.

---

### `_build/`
**Fully generated — never edit directly.** Deleted and recreated on every `preprocess.py` run.

After `preprocess.py` completes, `_build/` contains a complete Quarto project:
- `*.qmd` — one per paper (26 files), preprocessed from `source_md/`
- `corpus.qmd`, `references.qmd` — auto-generated index pages
- `_quarto.yml` — copied from `static/`, then rewritten with nested sidebar and `toc: false`
- `site-index.json`, `wdt_references.json`, `anchors.yml`, `wdt-contents.yml` — static endpoints
- `index.qmd`, `start-here.qmd`, `faq.qmd`, `glossary.qmd`, `summary.qmd` — from `static/pages/`, flattened
- `robots.txt`, `series.yml`, `wdt_references.bib` — from `static/seo/`, flattened
- `style/styles.css`, `style/apa.csl` — from `static/style/`, path preserved

After `quarto render _build`, the rendered site appears at `_build/_site/`. This is the directory uploaded to GitHub Pages by `deploy.yml`.

## Cross-reference system

In-text cross-references in source files use two syntactic patterns:

| Pattern | Example | Match type |
|---------|---------|------------|
| `(PAPER §X.Y)` | `(VAL §3.7)` | Paper with section |
| `(PAPER)` | `(BEHAV)` | Paper only |
| `PAPER §X.Y` | `WP §2.5` | Inline without parens |

`preprocess.py` resolves these via `anchors.yml` for deep links and `series.yml` (via `link_map`) for page-level links. Unresolved section keys produce a warning and fall back to the page root.

## Auto-generated pages

### `corpus.qmd` (Papers index)
Generated from `wdt_references.json` and `wdt-contents.yml`. Lists all 26 papers grouped by category with version, date, and status. Includes a collection-level JSON-LD block. Served at `/corpus.html`.

### `references.qmd` (External bibliography)
Generated from `wdt_references.json`. Alphabetical list of all 128 external references with type badges, DOI/URL links, and "cited in" links back to each WDT paper. Served at `/references.html`.

### `site-index.json`
Merged single-fetch navigation index combining paper metadata, full section hierarchy, and resolved anchor URLs. Intended for tools, search, and LLM consumption. Served at `/site-index.json`.

## Machine-readable static endpoints

Copied into `_build/` at each build and served as static files:

| Endpoint | Source | Contents |

## What is not yet in scope

- Interactive tools (tax calculator, revenue modeller) — reserved at `/tools/`
- Donations, contact, newsletter — reserved at `/about/` and `/contribute/`
- Citation key conversion (source files use prose APA; `@key` format is a future stage)
- PDF pipeline — separate, uses pandoc + LaTeX, entirely independent of this build
