    Commands and how-to (paste-ready)

    Run everything from the repository folder (outside OneDrive, for example C:\dev\Game). Examples are PowerShell; each button copies one block.

    1. Play or look at the game in Firefox

    Start the server and leave that terminal open (Ctrl+C stops it). It serves the repo root on port 8077 and sends no-cache, so a plain reload is enough.

    npm run serve

    Then paste into Firefox's address bar (a bare address opens the home page; any ? parameter loads the game directly):

    http://localhost:8077/spike/viewer/index.html

    Useful variants (add to the same address): ?dev=1 dev panel and hidden dev profile; ?bench=frames frame-time benchmark (2 skins x 4 views; keep the tab in front, hands off the mouse, press Copy results at the end); ?bench=rate max-speed ticks per second, 2D against 3D. Other pages: /spike/viewer/home.html, arena.html, balance.html, skin-lab.html.

    http://localhost:8077/spike/viewer/index.html?dev=1
http://localhost:8077/spike/viewer/index.html?bench=frames
http://localhost:8077/spike/viewer/index.html?bench=rate

    Port already in use, or "this site can't be reached": the server is not running in that terminal, or use another port and change 8077 in the address to match.

    $env:PORT=8090; npm run serve

    2. Get the latest code

    git checkout main
git pull
npm ci

    npm ci is only needed after package.json or the lock file changed. A tree with local changes: git status first.

    3. Tests and checks

    The checks picked by what changed (docs about 1 s, tools and tests 15 to 20 s, viewer about 150 s, simulation about 9 min). --list shows the plan without running it.

    npm run check -- --list
npm run check
    npm test -- --fast

    One test file only, and the whole quick tier regardless of what changed:

    npm run check -- --pattern=test091
npm run check -- --all

    Your own runs (the agents leave these to you): the full check with the headless browser checks (about 20 min, commit the log), the Firefox and Chromium determinism run, and a fresh-clone check before a release.

    npm run check:full -- --browser
npm run xplat
npm run clean-clone

    Browser checks need Playwright's browsers once: npx playwright-core install chromium firefox. A timing-sensitive browser check that fails on software graphics: add --browser-jobs=1.

    4. Balance and tuning (long runs, yours)

    npm run tournament -- --sets=120
npm run balance
npm run baselines

    baselines rewrites baselines.json after a simulation change (about 4 min); the result must match the agent's file exactly, otherwise that is a determinism bug.

    5. Agents and landing

    An agent works on brief/NNN-slug and ends with the landing command; it prints LANDED, NEEDS THE AUTHOR or FAILED. What it would do, without touching anything:

    npm run land -- --dry-run

    Stuck landing lock after a crashed run (never while a landing is really running):

    npm run land -- --unlock

    Paste to an agent when the usage meter is low, and to the next agent to resume (full text in docs/agents/handover.md):

    Stop work now. Commit everything as wip, push the branch, run `npm run handover -- --write`, fill in the progress block, then stop. Do not run checks.
    Read the brief and its progress block, `git log origin/main..HEAD`, and `git diff --stat origin/main`. Continue from Next. Do not re-explore. Run the Resume commands first.

    6. Housekeeping

    npm run briefs-index
npm run lane-plan
npm run format

    briefs-index regenerates the brief list after a brief moves; lane-plan refreshes only the History data of this page (needs a full clone, not a shallow one); format runs prettier. Pruning merged remote branches is in your to-do list above.
