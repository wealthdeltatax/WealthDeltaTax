# Lessons so far (guru, 2026-11-16)

Working list for the stage E synthesis. Neither model is fixed; the point is what v3 must do differently. Sources: `v1-inventory.md`, `v1-errors.md`, `v2-inventory.md`. Stage D (v2 complication and tests) is still to come, and each lesson below should be confirmed or dropped there.

1. **One definition per metric, written where code and paper both point to it.** C.1 is divided by TW(1) in `wdt_core.run_pair` (paper 5 tables) and by TW(alpha) in `wdt_analytics.c1` (paper 9) and in paper 5a's definition. The tolerant zone ends at 1.80 or 1.85 depending on the path (v1-errors B1). The `run_pair` docstring says the refactor changed it; nothing else was updated.
2. **Layers stayed clean only in v2, and only when someone wrote the rule down.** v1 has core-to-core and presentation-to-core imports (C3), four JSON sanitisers that behave differently (C1, B9) and capitalisation logic in four places (C5). v2's imports follow the layering (v2-inventory section 2.2).
3. **Hardcoded numbers and prose drift away from the parameter file.** `sweeps_core` marks tau_0 = 20% as canonical; the TOML says 15% (B7). The synthetic scenario's comments say 2% and 4%; the values are 7% and 8% (B8). Typed numbers sit in presentation text (A6). A table's N in its title differs from the N it ran at (B5).
4. **A renamed or moved file broke the pipeline with no test to catch it.** `rates_core` became `rates_core1.py`; 8 of 16 `run_all` entries cannot start (stage A) and a test file cannot import (E4). v2 has no run script at all, and the four tests its reference doc names do not exist (v2-inventory section 7).
5. **A silent convention change makes two models disagree on the same inputs.** v2 carries the post-surrender basis; at alpha 1.5, N 30, `net_pct` is +0.0132 (v2) against +0.0093 (v1). The note explaining it, `BASIS_CHANGE.md`, is cited and not tracked.
6. **Scope grew with no check that anything needed it.** v2's non-data Python is slightly smaller than v1's (17,729 against 18,136 lines), but its parameter file is 1,839 lines against 554, 58% of it `[rates]` with 101 scenarios. v2's figure names match none of the 19 names the papers embed. `eval_core.py` is orphaned (imports a module v2 lacks). Stage D attributes the growth.
7. **Outputs were not tied to the papers.** Paper 19 embeds three figures nothing produces and three with a doubled `fig_` prefix; figure prefixes and numbers are inconsistent across five families (D4). v2 tracks no outputs, so nothing can be compared with the papers.
8. **Import side effects and stale docs.** Two v2 WID scripts rewrite data files on import. `WDT_Model_Reference.md` names scripts that no longer exist (E1).

For v3 (011g) this implies: a metric register that papers and code both cite; a run script and a smoke test that fail loudly on a rename; every output named for the paper element it feeds; a parameter file with no duplicated or stale values; and a written reason for any change of convention.
