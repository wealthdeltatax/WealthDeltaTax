# WDT Site Architecture

**Project:** Public-facing GitHub Pages website for the Wealth Delta Tax research programme
**Generator:** Quarto (non-negotiable)
**Root directory:** `wdt-site/`

The site takes Markdown source files for 26 WDT papers, preprocesses them into Quarto-ready `.qmd` files, and publishes the result as a static HTML site via GitHub Pages. The build has two sequential Python steps followed by a Quarto render.

## Build sequence

```
registry/references.bib ─────────────────────────────────────────────────────────────────────┐
registry/internal.json ──────────────────────────────► pipeline/bib_to_json.py ──► registry/references.json
                                                                                              │
source/*.md ────────────────────────────────────────► pipeline/scrape_contents.py ──► registry/contents.yml
                                                                                              │
registry/contents.yml ──► pipeline/build_glossary.py ──► site/pages/glossary.md             │
                                                                                              │
registry/contents.yml ──► pipeline/build_anchors.py ──► registry/anchors.yml                │
                                                               │                              │
source/*.md ────────────────────────────────────────► pipeline/preprocess.py ──► _build/ ──► quarto render
registry/papers.yml ────────────────────────────────►         │
registry/references.json ───────────────────────────►         │
site/ ──────────────────────────────────────────────►         │
```

Run order (full): `pipeline/build_and_render.bat` → `scrape_contents.py --write` → `build_glossary.py` → `build_anchors.py` → `preprocess.py` → `quarto render _build`

Run order (anchors + preprocess only): `pipeline/build.bat` → `build_anchors.py` → `preprocess.py`

`preprocess.py` is a thin orchestrator. It first calls `bib_to_json.py` to regenerate `references.json`, then delegates every substantive step to the imported modules:
- **`bib_to_json.py`** — step (0): regenerate `references.json` from source files before anything else runs
- **`transforms.py`** — steps (1)–(5): strip LaTeX, convert cross-refs, convert biblio, inject front matter, JSON-LD
- **`pages/corpus.py`** — step (6): corpus.qmd
- **`pages/references.py`** — step (7): references.qmd
- **`pages/site_index.py`** — steps (8)–(9): copy machine-readable data, site-index.json
- **`diagrams.py`** — step (10): flowcharts.qmd with injected click directives
- **`config.py`** — path constants and registry loading (`load()` returns a `SiteConfig`)

## `pipeline/`

### `pipeline/build.bat`
Windows batch script that runs the anchors + preprocess steps only (`build_anchors.py` → `preprocess.py`). `quarto render _build` is run separately or via CI. `pause` on both failure and success keeps the terminal open.

**Note:** CI does not use `build.bat`. Use `build_and_render.bat` for a full local rebuild.

---

### `pipeline/build_and_render.bat`
Windows batch script for a **full local build** including all pipeline steps and the Quarto render in one command. Run order: `scrape_contents.py --write` → `build_glossary.py` → `build_anchors.py` → `preprocess.py` → `quarto render _build`.

Use this when paper headings or glossary terms have changed. Use `build.bat` for faster rebuilds when only source prose (not headings or section structure) has changed.

**Inputs/outputs:** same as running each step individually.

---

### `pipeline/scrape_contents.py`
Reads all source `.md` files and extracts their heading structure (section numbers and titles) to update `registry/contents.yml`. The `--write` flag commits the result to disk; without it the script is dry-run only.

Run before `build_anchors.py` and `build_glossary.py` whenever paper headings or section structure change. CI runs this first so that `contents.yml` is always current before downstream steps consume it.

**Inputs:** `source/*.md`
**Outputs:** `registry/contents.yml` (updated in place)
**Dependencies:** PyYAML
**Dependants:** `build_anchors.py`, `build_glossary.py`, `preprocess.py`

---

### `pipeline/build_glossary.py`
Generates the master glossary page by extracting term/definition pairs from each paper's own `# Glossary` section, deduplicating across papers (longer definition wins), then searching every section of every paper for mentions of each term to build cross-reference links.

**Inputs:** `source/*.md`, `registry/contents.yml`
**Outputs:** `site/pages/glossary.md` (**generated — never edit directly**)
**CLI:** `python pipeline/build_glossary.py --papers source --contents registry/contents.yml --out site/pages/glossary.md`
**Dependencies:** PyYAML
**Dependants:** `preprocess.py` (copies `site/pages/glossary.md` into `_build/` as `glossary.qmd`)

---

### `pipeline/build_anchors.py`
Derives the Quarto-generated HTML anchor ID for every section declared in `registry/contents.yml`, then writes `registry/anchors.yml`. This logic encodes Quarto's anchor rules and must be kept in sync with Quarto's actual rendering behaviour.

**Inputs:** `registry/contents.yml`
**Outputs:** `registry/anchors.yml`
**Dependencies:** `registry/contents.yml`, PyYAML
**Dependants:** `pipeline/preprocess.py`

Key anchor rules encoded:
- Pure integer top-level (`"1"`) → slugify title only
- Numeric sub-section (`"1.1"`) → strip number, slugify title only
- Single letter A–H → appendix style, dot added: `"A. Title"` → `a.-title`
- Single letter I–Z → VAL.B style, no dot: `"J Title"` → `j-title`
- Letter-dot-numeric (`"A.1"`) → full prefix kept: `"A.1 Title"` → `a.1-title`

---

### `pipeline/bib_to_json.py`
Generates `registry/references.json` by merging `registry/references.bib` (external bibliographic data) with `registry/internal.json` (internal papers, citations, and flags). Called automatically as step 0 of `preprocess.py` on every build, so `references.json` is always regenerated from its sources before any downstream module reads it.

**Never edit `references.json` directly** — changes will be overwritten on the next build. Edit `references.bib` for external reference data and `internal.json` for paper records, citations, and flags.

**Inputs:** `registry/references.bib`, `registry/internal.json`
**Outputs:** `registry/references.json` (overwritten on every build)
**Dependencies:** `bibtexparser`, `registry/references.bib`, `registry/internal.json`
**Dependants:** `preprocess.py` (calls `run()` as first step)

BibTeX type mapping:

| BibTeX `@type` | JSON `type` |
|----------------|-------------|
| `@article` | `journal_article` |
| `@book` | `book` |
| `@incollection` | `book_chapter` |
| `@unpublished` | `working_paper` |
| `@techreport` (NBER/CESifo/WID, or `type = "Working Paper"`) | `working_paper` |
| `@techreport` (other) | `report` |
| `@misc` | `institutional_report` |

---

### `pipeline/preprocess.py`
Thin orchestrator — calls `bib_to_json.run()` first to ensure `references.json` is fresh, then calls `config.load()` to get a `SiteConfig`, copies `site/` assets into `_build/`, and delegates every substantive build step to the imported modules. The run command is unchanged: `python pipeline/preprocess.py`.

**Inputs/outputs:** same registry files in, same `_build/` out.
**Dependencies:** all modules in `pipeline/`, PyYAML

---

### `pipeline/config.py`
Path constants, the shared `format_date()` utility, and registry loading. No side-effects on import — call `load()` explicitly in `main()`.

**Key exports:**
```python
SCRIPT_DIR, ROOT_DIR, SITE_DIR, SOURCE_DIR, BUILD_DIR
DIAGRAMS_DIR, CONTENTS_YML, ANCHORS_YML, REFERENCES_JSON, REGISTRY_YML
SITE_URL = "https://wealthdeltatax.org"
AUTHOR   = "K. Ogata"

def format_date(raw_date: Any) -> str | None: ...
    # Converts YYMMDD int/str (e.g. 260815) → ISO date string (e.g. 2026-08-15)
    # Used by transforms.py, corpus.py, and site_index.py

@dataclass
class SiteConfig:
    contents:   dict    # contents[SHORTCODE] = {page, title, sections}
    link_map:   dict    # link_map[SHORTCODE] = "page.html"
    anchor_map: dict    # anchor_map["WP§3.5"] = "wp.html#anchor-id"
    paper_meta: dict    # paper_meta[SHORTCODE] = internal-paper record
    refs_data:  dict    # full parsed references.json

def load() -> SiteConfig: ...
```

**Dependencies:** `registry/contents.yml`, `registry/anchors.yml`, `registry/references.json`, PyYAML
**Dependants:** `preprocess.py` (calls `load()`); all other modules (import constants and `format_date`)

---

### `pipeline/transforms.py`
The five per-paper text transforms, applied in order by `process_file()`.

**Functions:**
- `strip_latex(text)` — removes `\newpage`, `\medskip`, ``, and other LaTeX layout commands
- `convert_crossrefs(text, link_map, anchor_map)` — converts `(PAPER §X.Y)` and `PAPER §X.Y` patterns to markdown hyperlinks
- `convert_internal_bibliography(lines)` — converts `[CODE] ...` bibliography lines to styled `:::` divs
- `inject_front_matter(text, shortcode, paper_meta)` — enriches or creates YAML front matter (description, author, date, version, keywords)
- `build_jsonld(shortcode, paper_meta, link_map)` — returns a Quarto raw HTML block containing JSON-LD `ScholarlyArticle`
- `process_file(src, dest, shortcode, link_map, anchor_map, paper_meta)` — applies all five transforms and writes the result

**Dependencies:** `config` (for `AUTHOR`, `SITE_URL`, `format_date`), PyYAML
**Dependants:** `preprocess.py`

---

### `pipeline/diagrams.py`
Mermaid diagram preprocessing and `flowcharts.qmd` generation.

**Key exports:**
- `DIAGRAM_CLICK_MAP` — dict mapping Mermaid node IDs to `(shortcode, section_key, tooltip)`. **Edit this to add or update clickable nodes** — no `.mmd` source changes needed.
- `generate_flowcharts_qmd(build, link_map, anchor_map)` — reads the four `.mmd` files from `site/diagrams/`, injects click directives into the WDT diagrams, and writes `_build/flowcharts.qmd`

Click directives are injected only into WDT diagrams; UK comparison diagrams are embedded as-is.

**Zoom button JS:** The inline `<script>` uses a `MutationObserver` (not `DOMContentLoaded`) to attach zoom listeners, because Mermaid renders SVGs asynchronously after page load. `attachControls()` sets `minWidth` on `.cell` (the direct child of the overflow-scroll container) rather than on the SVG itself, clears `svg.style.maxWidth` (which Mermaid v10+ sets as an inline cap), and sets `svg.setAttribute("width", "100%")` and `svg.removeAttribute("height")` to override Mermaid's fixed-px attributes.

`BASE_PX = 1800` matches `.diagram-scroll svg { min-width: 1800px }` in `styles.css` — do not change one without updating the other.

**Dependencies:** `config` (for `DIAGRAMS_DIR`, `SITE_URL`), `site/diagrams/*.mmd`
**Dependants:** `preprocess.py`

---

### `pipeline/pages/corpus.py`
Generates `corpus.qmd` — the Papers index page listing all papers by category with version, date, and status. Includes a collection-level JSON-LD block.

**Key exports:** `generate_corpus_qmd(dest_path, link_map, paper_meta)`

---

### `pipeline/pages/references.py`
Generates `references.qmd` — alphabetical external bibliography with APA-style entries, type badges, DOI/URL links, and "cited in" links back to each WDT paper.

Citation `paper_id` values in `references.json` use abbreviated forms for dotted shortcodes (`LRA` → `LR.A`, `CORPA` → `CORP.A`, etc). The generator normalises these before `link_map` lookup so all "cited in" links resolve correctly.

A small number of entries pending author decisions on open flags are excluded from the public page and surfaced in a collapsed callout at the bottom. These are listed in `_PENDING_ORPHANS` in the generator; remove an entry from that frozenset once its flag is resolved.

**Key exports:** `generate_references_qmd(dest_path, refs_data, link_map)`

---

### `pipeline/pages/site_index.py`
Copies machine-readable registry files into `_build/` as static endpoints and generates `site-index.json`.

**Key exports:**
- `copy_machine_readable_assets(build, refs_data, anchor_map, contents, link_map)` — copies `references.json`, `anchors.yml`, `contents.yml`, `references.bib`, then calls `generate_site_index()`
- `generate_site_index(build, refs_data, anchor_map, contents, link_map)` — writes `site-index.json`

**Static copy behaviour:**
`FLATTEN_DIRS = {'pages'}` — only `site/pages/` is flattened to `_build/` root. All other `site/` contents preserve their relative paths.

## `registry/`

All data files consumed by the pipeline. Single source of truth for everything the pipeline needs to know about papers, sections, and references.

### Data management rules

| File | Maintained by | Rule |
|------|---------------|------|
| `contents.yml` | Hand | Edit whenever sections change. Drives everything. |
| `anchors.yml` | `build_anchors.py` | Never edit directly. Generated from `contents.yml` by `build_anchors.py`. |
| `papers.yml` | Hand | Edit when adding a new paper source file. |
| `internal.json` | Hand | Edit to add paper records, citations, and flags. The true source for all WDT-project data. |
| `references.bib` | Hand | Edit to add or correct external bibliographic entries. The true source for all external reference data. |
| `references.json` | `bib_to_json.py` | Never edit directly. Fully generated from `references.bib` + `internal.json` on every build. |

---

### `registry/contents.yml`
Master content map. Declares every paper (shortcode, output HTML filename, title) and every numbered section within each paper, in order.

Papers covered: WP, MF, LR, LR.A, LR.B, JUR, VAL, VAL.A, VAL.B, CORP, CORP.A, GOV, GOV.A, GOV.B, RATES, RATES.A, BEHAV, CLOSE, POL, PHASE1, ENV, SWEEPS, SWEEPS.A, FM, MOD, SCOPE (26 papers total).

Note: LR has `status: superseded` and has no source `.md` file or `papers.yml` entry — it appears in the corpus table as superseded but has no rendered paper page. SCOPE similarly has no source file; it is a register document not intended for standalone web publication. Both are intentional.

**Inputs:** maintained by hand; refreshed from source headings by `scrape_contents.py --write`
**Outputs:** consumed by `build_anchors.py` and `preprocess.py`; also copied into `_build/` as static endpoint `/wdt-contents.yml`

---

### `registry/anchors.yml`
Flat key→value map from every `PAPER§SECTION` lookup key to its resolved `page.html#anchor-id` URL. Used by `preprocess.py` to convert in-text cross-references into working hyperlinks.

**Never edit by hand.** Always generated by `build_anchors.py` from `contents.yml`. CI regenerates this file on every push, so it does not need to be manually committed after heading changes. The committed copy in the repo serves as a local reference and is used by `build.bat` (the fast local rebuild that skips `scrape_contents`).

Example entries:
```yaml
WP§3.5: wp.html#the-symmetric-loss-refund-mechanism
GOV.B§A.1: gov-b.html#a.1-the-taxpayer-chamber-tp
VAL.B§J: val-b.html#j-the-deferred-delta
```

---

### `registry/papers.yml`
Maps each paper shortcode to its source file glob pattern and its output `.qmd` filename in `_build/`. Decouples the source filename convention (which includes version numbers and dates) from the stable output names that anchors and cross-links depend on.

Each entry: `shortcode`, `source_glob`, `output`.

**Note on capitalisation:** the filename must be exactly `papers.yml` (lowercase). A capitalisation mismatch causes CI to fail on case-sensitive Linux filesystems even if it works locally on Windows.

---

### `registry/internal.json`
Hand-maintained source file for all WDT-project-specific data. Contains internal paper records, the citations junction table, and the open flags register. Combined with `references.bib` by `bib_to_json.py` to produce `references.json` on every build.

**Never add external reference data here** — external references belong in `references.bib`.

Top-level structure:
```
internal_papers[]        — WDT paper records (shortcode, title, version, status, outbound/inbound links, flags)
citations[]              — junction table: ref × paper × section, with relationship type
flags[]                  — open bibliographic issues with status, affected papers, and required action
alt_author_overrides{}   — alternate author string forms for specific ref IDs
```

**Inputs:** maintained by hand; extended by the `wdt-reference` skill
**Dependants:** `bib_to_json.py`

---

### `registry/references.bib`
Hand-maintained BibTeX source for all external references. Combined with `internal.json` by `bib_to_json.py` to produce `references.json`. Also referenced by `_quarto.yml` as `bibliography: references.bib` and copied into `_build/` as static endpoint `/references.bib`.

**Inputs:** maintained by hand; extended by the `wdt-reference` skill
**Dependants:** `bib_to_json.py`; Quarto's citation renderer

---

### `registry/references.json`
Fully generated on every build by `bib_to_json.py`. Merges all external reference data from `references.bib` with paper records, citations, and flags from `internal.json`. Consumed by `preprocess.py` for front matter injection, JSON-LD generation, corpus page, and references page. Also copied as static endpoint `/references.json`.

**Never edit directly** — changes will be overwritten on the next build.

Top-level structure:
```
meta                     — database version, generation date, record counts
external_references[]    — full bibliographic data (merged from references.bib)
internal_papers[]        — WDT paper records (from internal.json)
citations[]              — junction table: ref × paper × section (from internal.json)
flags[]                  — open bibliographic issues (from internal.json)
```

**Citation `paper_id` convention:** dotted shortcodes (LR.A, CORP.A, etc.) are stored as abbreviated IDs (LRA, CORPA) in the citations array. `pipeline/pages/references.py` normalises these before lookup.

## `source/`

Hand-authored Markdown source files for all papers. **Read-only from the pipeline's perspective — never modified by any script.**

Filename convention: `N.N_YYMMDD_WDT_[Title].md`. The `*` wildcard in `papers.yml` source globs absorbs the date component, keeping output filenames stable across revisions.

All papers contain LaTeX artifacts, cross-reference shorthand, and APA prose citations that `preprocess.py` transforms before Quarto sees them.

## `site/`

Hand-authored site content and configuration. Everything here is copied into `_build/` at build time — nothing in `site/` is generated.

### `site/_quarto.yml`
The Quarto project configuration. `preprocess.py` copies this to `_build/` verbatim. The sidebar is hand-maintained directly in this file.

Key configuration:
- `project.type: website`, `output-dir: _site`, `render: ["*.qmd"]`
- `site-url: https://wealthdeltatax.org`
- Search: overlay, navbar location
- **Navbar** (hand-maintained): Home, Start Here, FAQ, Full Overview, Papers, References (with dropdown of 17 main papers), Glossary
- **Sidebar** (hand-maintained): 7 sections mapping to all papers
- `page-footer`: CC BY 4.0 licence left, Zenodo DOI right
- `format.html`: theme `cosmo`, `toc: true`, `toc-depth: 3`, `css: style/styles.css`, `citations-hover: true`, `footnotes-hover: true`, `csl: style/apa.csl`
- `bibliography: references.bib`

**Note on `render`:** `project.render: ["*.qmd"]` is required. Without it, Quarto only renders files referenced by sidebar/navbar hrefs — the paper `.qmd` files would be silently skipped.

**Note on sidebar maintenance:** The sidebar is maintained directly in `site/_quarto.yml` and copied to `_build/_quarto.yml` unchanged. When adding a new paper, update the sidebar here as well as the navbar dropdown. LR (superseded) and SCOPE (register document) appear in the corpus table but not in the sidebar.

## `.github/`

### `.github/workflows/deploy.yml`
GitHub Actions workflow that builds and deploys the site on every push to `main`.

Build steps in order:
1. Checkout repo
2. Set up Python 3.11
3. Install Quarto (via `quarto-dev/quarto-actions/setup@v2`)
4. Install Python dependencies (`pip install pyyaml`)
5. Install BibTeX dependencies (`pip install bibtexparser`)
6. Run `python pipeline/scrape_contents.py --write` — refreshes `registry/contents.yml` from source headings
7. Run `python pipeline/build_glossary.py` — generates `site/pages/glossary.md`
8. Run `python pipeline/build_anchors.py` — regenerates `registry/anchors.yml` from the freshly updated `contents.yml`
9. Run `python pipeline/preprocess.py` — regenerates `registry/references.json` (step 0 inside preprocess), then generates `_build/`
10. Run `quarto render _build` — renders `.qmd` → HTML into `_build/_site/`
11. Upload `_build/_site/` as the Pages artifact
12. Deploy to GitHub Pages

CI regenerates `contents.yml`, `anchors.yml`, and `references.json` from source on every push. The committed copies of these files in the repo are kept as a local reference and for use by `build.bat`, but they do not need to be manually updated for CI to succeed.

## `_build/`
**Fully generated — never edit directly.** Deleted and recreated on every `preprocess.py` run.

After `preprocess.py` completes, `_build/` contains a complete Quarto project:
- `*.qmd` — one per paper (up to 26 files), preprocessed from `source/`
- `corpus.qmd`, `references.qmd` — auto-generated index pages
- `flowcharts.qmd` — auto-generated diagram page
- `_quarto.yml` — copied verbatim from `site/`
- `references.json`, `wdt-contents.yml`, `anchors.yml`, `references.bib` — static endpoints
- `site-index.json` — generated navigation index
- `research.qmd`, `index.qmd`, `faq.qmd`, `Project-Map.qmd` — from `site/pages/`, flattened
- `glossary.qmd` — from `site/pages/glossary.md` (generated by `build_glossary.py`), flattened and renamed to `.qmd`
- `apa.csl` — from `site/`, copied to root

## Cross-reference system

In-text cross-references in source files use two syntactic patterns:

| Pattern | Example | Match type |
|---------|---------|------------|
| `(PAPER §X.Y)` | `(VAL §3.7)` | Paper with section |
| `(PAPER)` | `(BEHAV)` | Paper only |
| `PAPER §X.Y` | `WP §2.5` | Inline without parens |

`transforms.py` (`convert_crossrefs`) resolves these via `registry/anchors.yml` for deep links and `registry/contents.yml` (via `link_map`) for page-level links. Unresolved section keys produce a warning and fall back to the page root.

## Sidebar behaviour

The left sidebar is hand-maintained in `site/_quarto.yml` and copied to `_build/_quarto.yml` unchanged by `preprocess.py`. It has two levels of nesting (section groups → papers). The right-hand TOC panel is enabled (`toc: true`, `toc-depth: 3`) and renders per-page section links.

**Known constraint:** Quarto sidebar section links are only interactively expandable when on that paper's page. This is a Quarto JS constraint, not a configuration issue.

## Auto-generated pages

### `corpus.qmd` (Papers index)
Generated from `registry/references.json` and `registry/contents.yml`. Lists all papers grouped by category with version, date, and status. Includes a collection-level JSON-LD block. Served at `/corpus.html`.

### `references.qmd` (External bibliography)
Generated from `registry/references.json`. Alphabetical list of all external references with APA-style formatting, type badges, DOI/URL links, and "cited in" links back to each WDT paper. A small number of entries pending author decisions on open flags are excluded and surfaced in a collapsed callout. Served at `/references.html`.

### `site-index.json`
Merged single-fetch navigation index combining paper metadata, full section hierarchy, and resolved anchor URLs. Intended for tools, search, and LLM consumption. Served at `/site-index.json`.

### `flowcharts.qmd` (Diagram page)
Generated by `generate_flowcharts_qmd()` in `pipeline/diagrams.py`. Embeds all four diagrams inline as Mermaid fenced code blocks within a tabset layout. WDT diagram nodes carry `click` directives pointing at paper sections. Served at `/flowcharts.html`.

## Adding a new paper — checklist

1. Add source `.md` file to `source/`
2. Add entry to `registry/papers.yml` (shortcode, source glob, output filename)
3. Add entry to `registry/contents.yml` (shortcode, page, title, sections)
4. Add paper record to `registry/internal.json` (internal_papers array)
5. Add the paper to the sidebar in `site/_quarto.yml`
6. Add the paper to the navbar dropdown in `site/_quarto.yml` if it should appear there
7. Add the paper to `site/pages/research.qmd` paper listing
8. Update `site/pages/Project-Map.qmd` if the summary document covers the new paper
