# WDT Site Architecture

**Project:** Public-facing GitHub Pages website for the Wealth Delta Tax research programme
**Generator:** Quarto (non-negotiable)
**Root directory:** `wdt-site/`

The site takes Markdown source files for 26 WDT papers, preprocesses them into Quarto-ready `.qmd` files, and publishes the result as a static HTML site via GitHub Pages. The build has two sequential Python steps followed by a Quarto render.

## Build sequence

```
registry/references.bib ─────────────────────────────────────────────────────────────────────┐
registry/internal.json ──────────────────────────────► pipeline/bib_to_json.py ──► registry/references.json
                                                                                              │
source/*.md ────────────────────────────────────────► pipeline/scrape_contents.py ──► registry/contents.yml
                                                                                              │
registry/contents.yml ──► pipeline/build_glossary.py ──► site/pages/glossary.md             │
                                                                                              │
registry/contents.yml ──► pipeline/build_anchors.py ──► registry/anchors.yml                │
                                                               │                              │
source/*.md ────────────────────────────────────────► pipeline/preprocess.py ──► _build/ ──► quarto render
registry/papers.yml ────────────────────────────────►         │
registry/references.json ───────────────────────────►         │
site/ ──────────────────────────────────────────────►         │
```

Run order (full): `pipeline/build_and_render.bat` → `scrape_contents.py --write` → `build_glossary.py` → `build_anchors.py` → `preprocess.py` → `quarto render _build`

Run order (anchors + preprocess only): `pipeline/build.bat` → `build_anchors.py` → `preprocess.py`

`preprocess.py` is a thin orchestrator. It delegates every substantive step to the imported modules:
- **`bib_to_json.py`** — step (0): regenerate `references.json` from `.bib` + `internal.json` before anything else runs
- **`config.extract_paper_meta()`** — step (0.5): extract shortcode, version, word count, and other metadata from each source `.md` file's own front matter and revision history. Shortcode is read from the file itself, not from `papers.yml`. Results populate `paper_meta` which is passed into `cfg.load(paper_meta=paper_meta)`.
- **`transforms.py`** — steps (1)–(6): strip LaTeX, fix image paths, convert cross-refs, convert biblio, inject front matter + body blocks, JSON-LD + under-construction banner
- **`pages/corpus.py`** — step (6 gen): corpus.qmd
- **`pages/references.py`** — step (7 gen): references.qmd
- **step (8)** — copy static assets from `site/` into `_build/` (inline in `preprocess.py`)
- **`pages/site_index.py`** — steps (9)–(10): copy machine-readable data, site-index.json
- **`diagrams.py`** — step (11): render `.mmd` → PNG via `mmdc`, then write flowcharts.qmd referencing the PNGs
- **`link_map.py (in pipeline/)`** — step (12): generate `_build/link-map.html` from `internal_papers` in `refs_data`
- **`config.py`** — path constants, `extract_paper_meta()`, `parse_human_date()`, `load(paper_meta)`

## `pipeline/`

### `pipeline/build.bat`
Windows batch script for a full local build **without** the Quarto render step. Run order: `scrape_contents.py --write` → `build_glossary.py` → `build_anchors.py` → `preprocess.py`. Each step exits with error and `pause` on failure; `pause` on success keeps the terminal open.

Use this when you want to regenerate `_build/` and inspect it before rendering, or when running `quarto render _build` separately.

**Note:** The arch doc previously described this as running only `build_anchors.py` + `preprocess.py`. That was wrong — it runs the full pipeline minus the render step, identical to `build_and_render.bat` except for the final `quarto render _build`.

---

### `pipeline/build_and_render.bat`
Windows batch script for a complete local build including the Quarto render. Run order: `scrape_contents.py --write` → `build_glossary.py` → `build_anchors.py` → `preprocess.py` → `quarto render _build`. Each step exits on failure with `pause`; `pause` on success.

Adds Quarto to `PATH` explicitly (`C:\Users\kyleo\AppData\Local\Programs\Quarto\bin`) so `quarto` is available in `cmd.exe` without a system-level PATH entry. If running on a different machine, update this path or ensure Quarto is on the system PATH.

---

### `pipeline/scrape_contents.py`
Scans source `.md` files and reports / writes their heading structure to `registry/contents.yml`. Shortcodes are read from each file's own YAML front matter (not from `papers.yml`).

**Run modes:**

| Flag | Behaviour |
|------|-----------|
| *(none)* or `--report` | Print the full report for each paper; write nothing |
| `--write` | Write CLEAN entries to `contents.yml`; flag edge cases in console output |
| `--dry-run` | Show a unified diff of what `--write` would change without touching the file |

**Filtering:** Pass shortcodes as positional arguments to limit processing to specific papers: `python pipeline/scrape_contents.py WP RATES`.

**Heading classification:**

- **CLEAN** — key extracted automatically (numeric `# 1`, `## 1.1`, `### 3.4.1`; lettered `# A.`, `## A.1`; letter-dot-numeric `A.1`). Written to `contents.yml` on `--write`.
- **SKIPPED** — never written: headings with `{.unnumbered}` or `{.unlisted}`; prose-only headings matching: `abstract`, `glossary`, `internal bibliography`, `revision history`, `keywords`, `author disclosure`.
- **EDGE CASE** — flagged for manual resolution: appendix `h1` with no letter prefix; any `h1` with no numeric/letter prefix. These are reported but never written automatically.

**Merge behaviour:** `--write` does not clobber existing entries in `contents.yml` — it only adds missing keys. Manual overrides in `contents.yml` are preserved.

**Inputs:** `source/*.md` (exact filenames from `papers.yml`), `registry/contents.yml` (read-merge-write)
**Outputs:** `registry/contents.yml` (updated in place; unchanged if already current)
**Dependencies:** PyYAML
**Dependants:** `build_anchors.py`, `build_glossary.py`, `preprocess.py`

---

### `pipeline/build_glossary.py`
Generates `site/pages/glossary.md` from each paper's own `# Glossary` section. No seed file; no scraping of bold text outside glossary sections.

**Algorithm:**
1. For each `.md` paper: locate the paper's `# Glossary` heading (strictly scoped — stops at the next heading of same or higher level). Extract `**Term:** definition` pairs.
2. Deduplicate across papers: longer definition wins.
3. For each term, search every section of every paper for mentions. Each search section's scope includes all nested subsections. Term variants searched: exact, lowercase, sentence-case (first letter lowercased), acronym expansion (e.g. `"Sovereign Wealth Fund (SWF)"` → also searches `"SWF"` and `"Sovereign Wealth Fund"`), and naive plurals of all of the above.
4. Output: alphabetical, with letter `<h3>` anchor sections (raw HTML, not Quarto `##` headings, to prevent Quarto mangling) and a jump bar of only letters that have entries.

**Paper→shortcode mapping:** Uses the front matter `title:` field (normalised fuzzy match against `contents.yml` titles) — not `shortcode:`. If the title does not match any entry in `contents.yml`, the paper is skipped for cross-reference search (but its glossary terms are still collected).

**Jump bar:** Only letters with at least one entry are included. Rendered as a raw `{=html}` block with `.wdt-glossary-jumpbar` class.

**Letter anchors:** Raw HTML `<h3 id="glossary-a" class="wdt-glossary-letter">A</h3>` — bypasses Quarto's heading anchor generation entirely.

**Inputs:** `source/*.md`, `registry/contents.yml`
**Outputs:** `site/pages/glossary.md` (**generated — never edit directly**)
**CLI:** `python pipeline/build_glossary.py --papers source --contents registry/contents.yml --out site/pages/glossary.md`
**Dependencies:** PyYAML
**Dependants:** `preprocess.py` (copies to `_build/glossary.qmd`)

### `pipeline/build_anchors.py`
Derives the Quarto-generated HTML anchor ID for every section in `registry/contents.yml`, writes `registry/anchors.yml`. Must be run after any `--write` to `contents.yml`. The logic encodes Quarto's observed anchor rules and must stay in sync with Quarto's actual rendering.

**`slugify(text)`:** Converts heading text to a Quarto anchor ID:
- Lowercases, removes `( ) : ' " ? ,`
- Em-dash and en-dash → space
- Non-alphanumeric (except `-` and `.`) → space
- Whitespace → hyphens; multiple hyphens collapsed

**`make_anchor(section_key, section_title)`:** Four key patterns from `contents.yml`:

| Key pattern | Example | Anchor rule |
|-------------|---------|-------------|
| Pure integer | `"1"`, `"10"` | `slugify(title)` — Quarto *does* generate an anchor even for `h1` |
| Numeric dotted | `"1.1"`, `"3.4.1"` | `slugify(title)` — strip number prefix, slugify title only |
| Single letter A–H | `"A"`, `"B"` | Appendix style: `slugify("A. " + title)` → `a.-the-chambers-in-full` |
| Single letter I–Z | `"J"`, `"K"` | VAL.B style (no dot): `slugify("J " + title)` → `j-the-deferred-delta` — **unverified in browser; console warning emitted** |
| Letter-dot-numeric | `"A.1"`, `"F.2.1"` | Full prefix: `slugify("A.1 " + title)` → `a.1-the-taxpayer-chamber-tp` |

**Output:** `anchors.yml` — flat `PAPER§KEY: page.html#anchor` map, alphabetically sorted. Top-level numeric sections (`"1"`) still get an anchor entry (they are not mapped to page root). Unverified I–Z single-letter sections are flagged in console output with their resolved URLs for manual browser verification.

**Inputs:** `registry/contents.yml`
**Outputs:** `registry/anchors.yml` (overwritten on every run)
**Dependencies:** PyYAML
**Dependants:** `preprocess.py`

### `pipeline/bib_to_json.py`
Generates `registry/references.json` by merging `registry/references.bib` with `registry/internal.json`. Called automatically as step 0 of `preprocess.py`; can also be run standalone.

**Never edit `references.json` directly** — overwritten on every build.

**BibTeX type mapping:**

| BibTeX `@type` | JSON `type` | Notes |
|----------------|-------------|-------|
| `@article` | `journal_article` | |
| `@book` | `book` | |
| `@incollection` | `book_chapter` | |
| `@unpublished` | `working_paper` | |
| `@techreport` | `working_paper` | if `institution` contains NBER/CESifo/WID/WID World, or `type = "Working Paper"` |
| `@techreport` | `report` | all other techreports |
| `@misc` | `institutional_report` | |

**BibTeX field mapping:**

| BibTeX field | JSON field | Notes |
|---|---|---|
| `author` | `authors[]` | Parsed to `{last, first}`. Institutional detection: no comma anywhere in the full string → `{last: name, first: null}`. |
| `year` | `year` (int) | |
| `title` | `title` | LaTeX braces stripped, diacritics decoded to unicode |
| `journal` | `journal` | |
| `volume` | `volume` (str) | |
| `number` | `issue` for `@article`; `number` for `@techreport` | |
| `pages` | `pages` | `--` → `–` (en-dash) |
| `doi` | `doi` | |
| `url` | `url` | |
| `publisher` / `institution` / `howpublished` | `publisher` | First non-null wins |
| `series` | `series` | |

**`note` field parsing:** The `note` field carries three kinds of structured content:
- `"Verified YYYY-MM-DD[.]..."` → `verified: true`, `verified_date: YYMMDD`
- `"Flag N: ..."` → `flag_ids += ["flag_NN"]` (only IDs present in `internal.json` flags are kept — prevents phantom IDs)
- Remainder → `verification_notes` (LaTeX stripped, flag lines removed)

**Merge logic (`merge()`):** Builds three lookup indexes from `internal.json`:
1. `citation_index` — `ref_id → [citation_ids]` from the citations array
2. `flag_index` — `ref_id → {flag_ids}` from `flags[].affects_refs`
3. `alt_map` — `ref_id → [alt_author_forms]` from `alt_author_overrides`

For each external ref: `citation_ids` = sorted citations for that ref; `flag_ids` = merged (note-parsed + flag_index), filtered to `valid_flag_ids` only; `alt_author_forms` = from `alt_map`.

**Output structure:**
```json
{
  "meta": { "version": "0.1", "date": "YYMMDD", "generated_by": "...",
            "total_external_refs": N, "total_internal_papers": N,
            "total_citations": N, "total_flags": N },
  "external_references": [...],
  "internal_papers": [...],
  "citations": [...],
  "flags": [...]
}
```

**`run(bib_path, internal_path, output_path)`:** All three paths accept overrides (defaults to registry paths) — useful for testing.

**Inputs:** `registry/references.bib`, `registry/internal.json`
**Outputs:** `registry/references.json`
**Dependencies:** `bibtexparser`
**Dependants:** `preprocess.py` (calls `run()` as step 0)

### `pipeline/preprocess.py`
Thin orchestrator. Run order inside `main()`:

1. Calls `bib_to_json.run()` (step 0) to regenerate `references.json`.
2. Reads `papers.yml` for the source-filename → output-filename mapping. Each entry uses `source` (exact filename) and `output` — **not** a glob; the date is baked into the exact filename.
3. Calls `cfg.extract_paper_meta(src_path)` on each source file (step 0.5) to extract shortcode, version, word count, and other metadata from the file's own YAML front matter and revision history. Shortcode comes from the source file itself, not from `papers.yml`.
4. Calls `cfg.load(paper_meta=paper_meta)` to build the `SiteConfig`.
5. Deletes and recreates `_build/`.
6. Copies `site/` assets into `_build/` (step 8 — see asset copy rules below).
7. Copies `site/model/OUTPUTS/` → `_build/figures/` (if the directory exists).
8. Calls the auto-generated page generators: `corpus.qmd`, `references.qmd`, `flowcharts.qmd`, machine-readable assets + `site-index.json`.
9. Calls `process_file()` on each paper.

**Asset copy rules (step 8):**

| Source path | Behaviour |
|-------------|-----------|
| `site/pages/*.md` | Flattened to `_build/` root; `.md` → `.qmd`; `strip_latex` + `convert_crossrefs` applied |
| `site/pages/*.qmd` or other | Flattened to `_build/` root; copied verbatim |
| `site/model/*.html` | Copied to `_build/model/`; **wrapped in Quarto front matter** via `_wrap_tool_html()`, saved as `.qmd` |
| `site/model/*.py` or `*.toml` | Copied to `_build/model/` verbatim — these are **runtime files** that Pyodide loads in the browser |
| `site/model/` other files | Copied to `_build/model/` verbatim |
| Everything else in `site/` | Copied preserving relative path |

**`_TOOL_META`:** A dict in `preprocess.py` mapping tool HTML stem → `(title, description)`. These become the Quarto front matter `title` and `description` for each tool page. When adding a new tool, add an entry here.

**`_wrap_tool_html(html, title, description)`:** Wraps a body-fragment HTML file in Quarto front matter (`title`, `description`, `toc: false`) and a `{=html}` raw pass-through block with `<!-- quarto-disable-processing=true -->`. This is how HTML tools are rendered by Quarto without Quarto modifying their content.

**Inputs:** `registry/papers.yml`, source `.md` files, all `site/` assets
**Outputs:** `_build/` (complete Quarto project)
**Dependencies:** all modules in `pipeline/`, PyYAML

### `pipeline/transforms.py`
Six per-paper text transforms applied in order by `process_file()`.

**Functions (in call order):**

1. **`strip_latex(text)`** — removes `\newpage`, `\medskip`, `\bigskip`, `\\`, `\vspace{...}`, `\hspace{...}`, `\setcounter{...}`, and other LaTeX layout/spacing commands.

2. **`fix_image_paths(text)`** — rewrites all Markdown image paths to `figures/<filename>`. Source files may reference images as `../figures/foo.png`, `figures/foo.png`, or `site/model/OUTPUTS/RATES/foo.png` — all become `figures/foo.png`. This is correct because `preprocess.py` copies all images from `site/model/OUTPUTS/**/*` into `_build/figures/` (flat), and Quarto renders papers at the `_build/` root. HTTP/data URLs are left unchanged.

3. **`convert_crossrefs(text, link_map, anchor_map)`** — converts `(PAPER §X.Y)` and `PAPER §X.Y` patterns to Markdown hyperlinks. Resolves deep links via `anchor_map`; falls back to page root with a warning if section not found.

4. **`convert_internal_bibliography(lines)`** — converts `[CODE] description...` lines into styled `::: {.internal-bibliography}` div blocks.

5. **`inject_front_matter(text, shortcode, paper_meta)`** — enriches the file's existing YAML front matter with computed fields (`author`, `date`, `version`, `word_count`; `keywords` if not already present). Also injects two body blocks **before the revision history table**: a `.paper-meta` div (version, date, word count display) and a `.paper-disclosure` div (AI assistance / funding disclosure, sourced from `config.DISCLOSURE`).

6. **`inject_under_construction(text, shortcode, paper_meta)`** — prepends a `🚧 THIS PAPER IS UNDER CONSTRUCTION 🚧` banner (as a raw HTML `{=html}` block) immediately after the front matter fence for any paper whose version string starts with `"0."`.

7. **`build_jsonld(shortcode, paper_meta, link_map)`** — appended after the body. Returns a `{=html}` block containing a JSON-LD `ScholarlyArticle` record. Dates come from `version_date` (ISO string from `extract_paper_meta`); keywords merge paper-specific terms with standard WDT tags; `relatedLink` includes all outbound and inbound paper cross-references.

**`process_file(src, dest, shortcode, link_map, anchor_map, paper_meta)`** — orchestrates all seven calls in order and writes the result to `dest`.

**Imports from `config`:** `AUTHOR`, `AFFILIATION`, `DISCLOSURE`, `SITE_URL`
**Dependencies:** PyYAML
**Dependants:** `preprocess.py`

### `pipeline/pages/site_index.py`
Copies machine-readable registry files into `_build/` as static endpoints and generates `site-index.json`.

**`copy_machine_readable_assets(build, refs_data, anchor_map, contents, link_map)`**
Copies four registry files into `_build/`, then calls `generate_site_index()`:

| Source | Destination endpoint |
|--------|---------------------|
| `registry/references.json` | `/references.json` |
| `registry/anchors.yml` | `/anchors.yml` |
| `registry/contents.yml` | `/wdt-contents.yml` |
| `registry/references.bib` | `/references.bib` |

**`generate_site_index(build, refs_data, anchor_map, contents, link_map)`**
Writes `site-index.json` — a single-fetch combined navigation + search index.

**Structure:**
```json
{
  "meta": { "generated": "ISO timestamp", "site": "...", "papers": N,
            "anchors": N, "search_records": N, "description": "..." },
  "papers": [...],
  "anchors": { "WP§1.1": "wp.html#...", ... },
  "search": [...]
}
```

**`papers` array:** One record per paper with `shortcode`, `title`, `url`, `version`, `version_date`, `status`, `outbound_internal`, `inbound_internal`, `sections[]`. Each section has `key`, `title`, `anchor`, `url`. `version_date` is formatted via `_format_date()` (the legacy YYMMDD function) from `internal_papers` records in `refs_data` — note this is the `internal.json` version date, not the `extract_paper_meta()` ISO date.

**`search` array:** Flat records for the right-panel search widget. Two kinds:
- `kind: "paper"` — one per paper; `text` = paper title; `href` = paper URL
- `kind: "section"` — one per section; `text` = extracted body prose; `href` = resolved anchor URL

Section text is extracted from the **generated `.qmd` files** in `_build/` (not source `.md`), so the search index reflects the transformed text that Quarto will render. `_extract_sections()` scopes each section's text to include all nested subsections (stops at the next heading of same or higher level). Code blocks, HTML tags, image markup, and emphasis markers are stripped; link text is retained.

**Note on `_format_date` import:** `site_index.py` explicitly imports `_format_date` (the private legacy function) from `config`. This is intentional — `internal_papers` records store dates as YYMMDD integers, not ISO strings. The private import is expected and not a bug.

**Key exports:** `copy_machine_readable_assets(...)`, `generate_site_index(...)`

## Cross-reference system

In-text cross-references in source files use two syntactic patterns:

| Pattern | Example | Match type |
|---------|---------|------------|
| `(PAPER §X.Y)` | `(VAL §3.7)` | Paper with section |
| `(PAPER)` | `(BEHAV)` | Paper only |
| `PAPER §X.Y` | `WP §2.5` | Inline without parens |

`transforms.py` (`convert_crossrefs`) resolves these via `registry/anchors.yml` for deep links and `registry/contents.yml` (via `link_map`) for page-level links. Unresolved section keys produce a warning and fall back to the page root. Both `link_map` and `anchor_map` are keyed by shortcode; shortcodes come from source file front matter via `extract_paper_meta()`.

The left sidebar is hand-maintained in `site/_quarto.yml` and copied to `_build/_quarto.yml` unchanged by `preprocess.py`. It has two levels of nesting (section groups → papers). The right-hand TOC panel is enabled (`toc: true`, `toc-depth: 2`) — only `##` level headings appear in the per-page TOC; `###` and below are excluded.

**Known constraint:** Quarto sidebar section links are only interactively expandable when on that paper's page. This is a Quarto JS constraint, not a configuration issue.

## Auto-generated pages

### `corpus.qmd` (Papers index)
Generated from `registry/references.json` and `registry/contents.yml`. Lists all papers grouped by category with version, date, and status. Includes a collection-level JSON-LD block. Served at `/corpus.html`.

### `references.qmd` (External bibliography)
Generated from `registry/references.json`. Entries grouped under `## A`, `## B`, … letter headings with per-letter TOC links (enabled via `toc: true` in generated front matter). Each entry shows APA-style citation, type badge, DOI/URL link, verified badge, and "cited in" links to WDT papers. Pending-decision entries (currently none) appear in a collapsed callout. Served at `/references.html`.

### `site-index.json`
Single-fetch index combining paper metadata, full section hierarchy, resolved anchor URLs, and a flat searchable section text corpus. Four top-level keys: `meta`, `papers`, `anchors`, `search`. The `search` array powers the right-panel search widget — one record per paper (title search) and one per section (body text search). Text is extracted from generated `.qmd` files in `_build/`, not from source `.md`. Served at `/site-index.json`.

### `flowcharts.qmd` (Diagram page)
Generated by `generate_flowcharts_qmd(build)` in `pipeline/diagrams.py`. Renders `.mmd` sources to PNG via `mmdc`, then writes a prose-framed `.qmd` page embedding those PNGs with a client-side lightbox (click to expand; ESC to close).

Page structure:
- **§complexity** — editorial framing and a structural metrics table comparing WDT vs UK chart complexity (nodes, decisions, edges, tax regimes)
- **§overview** — WDT skeleton and UK skeleton diagrams side-by-side
- **§full-detail** — WDT full chart and UK full chart side-by-side
- **§core-mechanic** — Bidirectional diagram (solo), with framing prose

All five `.mmd` diagrams are now included. PNG outputs land in `_build/diagrams/` at 3600px width. Served at `/flowcharts.html`.

## Known constraints

**Sidebar cross-page expansion is not supported by Quarto.** Section links in the sidebar are only interactively expandable when on that paper's page. This is a Quarto JS constraint, not a configuration issue.

**`site/model/` `.py` and `.toml` files are deployed to `_build/model/`** and served publicly. This is intentional — they are loaded client-side by Pyodide. The numbered output scripts (`5_3`, `5_4`, etc.) are also deployed but are not called by Pyodide; they are inert on the server. `.bat` files are not in `_TOOL_RUNTIME_SUFFIXES` and fall through to the verbatim-copy else branch — verify whether they should be excluded.

**`mmdc` is installed on the CI runner** via the Install Mermaid CLI step in `deploy.yml`. The Puppeteer sandbox config is correctly set up. On local Windows builds, `mmdc` must be installed separately: `npm install -g @mermaid-js/mermaid-cli`.

**`svg-pan-zoom.min.js` may now be unused.** The diagrams pipeline has moved from browser-side Mermaid SVG rendering (which used this library for zoom) to static PNGs with a custom lightbox. Verify whether this file is still referenced anywhere in `site/style/` or `site/_quarto.yml` before removing it.

## Adding a new paper — checklist

1. Add source `.md` file to `source/` with a YAML front matter block containing at minimum: `shortcode`, `title`, `status`, `keywords`
2. Add a revision history table (` ### Revision History`) with at least one data row — `extract_paper_meta()` reads version and date from here
3. Add entry to `registry/papers.yml` — `source` (exact filename) and `output` (e.g. `wp.qmd`). Shortcode is not needed here; it is read from the file's front matter.
4. Run `python pipeline/scrape_contents.py --dry-run` to preview what would be written, then `--write` to add the paper's sections to `registry/contents.yml`
5. Run `python pipeline/build_anchors.py` to regenerate `registry/anchors.yml`
6. Add paper record to `registry/internal.json` (internal_papers array)
7. Add the paper to the sidebar in `site/_quarto.yml` under the appropriate section
8. If it is a main paper (not an appendix), add it to the navbar Papers dropdown in `site/_quarto.yml`; appendix papers go in the sidebar only
9. Add the paper to `site/pages/research.md` paper listing
10. Update `site/pages/Project-Map.md` if the summary document covers the new paper
11. Add the shortcode and group to `_GROUPS` in `pipeline/link_map.py`

## Adding a new tool page — checklist

1. Author the HTML tool page (body fragment, no `<html>`/`<head>`) in `site/model/`
2. Add an entry to `_TOOL_META` in `pipeline/preprocess.py` — `"stem": ("Page title", "Description string")` — so the Quarto front matter is populated correctly
3. If the tool uses Pyodide to run Python, add the required `.py` and `.toml` model files to `site/model/` — they will be copied to `_build/model/` automatically
4. If the tool requires locally-generated static outputs (figures, tables), add the corresponding output script(s) to `site/model/` and add the run command to `site/model/run_all.bat`; outputs go to `site/model/OUTPUTS/` and are copied to `_build/figures/`
5. Add any tool-specific CSS to `site/style/tools.css`
6. Link to the new tool from `site/model/tools_index.html`
7. Add a navbar or sidebar entry in `site/_quarto.yml` if the tool should be discoverable from navigation
